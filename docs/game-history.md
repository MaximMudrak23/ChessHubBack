# Історія ігор

`GET /game/history?page=1&limit=20`

Заголовок авторизації: `Authorization: Bearer <JWT>`.
Повертає тільки завершені ігри користувача з JWT, включно з іграми проти ботів.
Параметри `userId` не змінюють користувача, для якого завантажується історія.

```json
{
  "games": [
    {
      "id": "507f1f77bcf86cd799439010",
      "white": {
        "name": "Alice",
        "avatarURL": "/uploads/alice.png",
        "elo": 1200
      },
      "black": {
        "name": "Bob",
        "avatarURL": "/uploads/bob.png",
        "elo": 1300
      },
      "result": "win",
      "movesCount": 23,
      "finishedAt": "2026-11-18T12:30:00.000Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 45,
    "totalPages": 3,
    "hasMore": true
  }
}
```

- `id`: використовуйте для переходу на frontend `/game/:id`. Деталі гри доступні через наявний `GET /game/by-id/:id`.
- `white`, `black`: знімки гравців на початку гри. `elo` — рейтинг до його зміни за результатом цієї гри. Поточні профілі не завантажуються. Відсутні історичні `name`, `avatarURL`, `elo` повертаються як `null`.
- `result`: `win`, `loss` або `draw` відносно авторизованого користувача.
- `movesCount`: кількість номерів ходів (`moves.length`), а не окремих півходів. Наприклад, після `1. e4 e5 2. Nf3` це `2`; до першого ходу — `0`.
- `finishedAt`: дата завершення у форматі ISO 8601 UTC. Для нових ігор фіксується при завершенні, до оновлення рейтингів. Для старих ігор без `finishedAt` використовується `updatedAt`; це приблизна дата, якщо запис редагували після завершення.

Сортування: дата завершення за спаданням, при однаковій даті — `_id` за спаданням.
Старі завершені записи без коректного `winner` не включаються: для них неможливо визначити результат.

`page` — додатне ціле число, типово `1`. `limit` — ціле число від `1` до `100`, типово `20`.
Порожня історія повертає `games: []`, `total: 0`, `totalPages: 0`, `hasMore: false`.
Сторінка за межами історії повертає `games: []` зі збереженою загальною кількістю ігор.
Нові завершені ігри можуть зсувати сторінки; під час оновлення списку починайте зі сторінки `1`.

Помилки: `401` — відсутня або некоректна авторизація; `400` — некоректна пагінація; `500` — помилка сервера.

Перевірка: `npm test`, `npm run build`. Автоматичні тести перевіряють HTTP, DTO, побудову MongoDB-запиту та завершення ігор із підміною звернень до БД. Виконання агрегації на справжній MongoDB потребує окремої інтеграційної перевірки.
